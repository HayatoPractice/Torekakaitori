以下の手順で、アプリ作成原本とホームページ作成原本の整合性を確認してください。

## Step 1：原本間の新着差分を確認

```bash
python3 scripts/compare_origins.py
```

HP側（ホームページ作成原本）の新着コミットを確認し、アプリ作成原本への活用候補を記録する。

**判断基準：**
- ルール追加・改善の場合 → APP_SHARED_RULES.md への採用を検討
- スクリプト追加の場合 → scripts/ への移植を検討
- コマンド追加の場合 → .claude/commands/ への追加を検討
- HP固有（WordPress・デザインルール等）の場合 → スキップ

---

## Step 2：HP側ルールファイルの新着セクションを確認

HP側の WEB_SHARED_RULES.md で追加・更新されたセクションを特定し、APP側の対応セクションと比較する。

```bash
git -C /Users/sasakihayato/ホームページ作成/ホームページ作成原本 log --since="$(cat /Users/sasakihayato/.origin_watch/last_check.txt 2>/dev/null || date -v-30d +%Y-%m-%d)" --name-only --pretty=format: | grep -E "\.md$" | sort -u
```

変更があった .md ファイルを確認し、内容を参照して APP 側への採用可否を判断する。
（HP 側フォルダは読み取りのみ。一切編集しない）

---

## Step 3：APP_SHARED_RULES.md 内部の整合性チェック

以下の観点で APP_SHARED_RULES.md を確認する：

1. **セクション番号の重複・欠番がないか**
```bash
grep "^## [0-9]" DOCS/APP_SHARED_RULES.md | grep -oE "^## [0-9]+" | sort -n
```

2. **相互参照が正しいか**（「§XX を参照」という記述のセクション番号が実在するか）
```bash
grep -o "§[0-9]\+" DOCS/APP_SHARED_RULES.md | sort -u
```

3. **矛盾するルールがないか**（目視で確認）
   - 「必ず〇〇すること」と「〇〇してはいけない」が同じ内容に適用されていないか
   - 同じ手順が複数セクションに重複して記載されていないか

---

  - セクション数：§1〜§N
  - 重複箇所：[あれば記載。なければ「なし」]

---

## Step 5：採用の実行（ユーザー確認後）

採用候補をユーザーに提示し、確認を得てから APP_SHARED_RULES.md に追記する。
追記後は `python3 scripts/sync_to_apps.py` で全アプリへ配布する。

> ⚠️ HP 側フォルダへの書き込みは絶対禁止。読み取りのみ。
> ⚠️ sync_to_apps.py の対象はアプリ作成関連フォルダのみ。HP 側には同期しない。
