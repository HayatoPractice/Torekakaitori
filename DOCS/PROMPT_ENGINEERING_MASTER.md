# プロンプトエンジニアリング・マスターガイド

Anthropic推奨の、高品質な出力を安定して得るための高度なテクニック集です。

## 1. 構造化プロンプト (XMLタグの活用)

すべての指示、データ、思考プロセスをXMLタグで囲み、AIが情報を混同しないようにします。

-   `<thinking>`: 内部的な推論、リスク分析。
-   `<instructions>`: 具体的な命令。
-   `<example>`: Few-shot用の例示。
-   `<context>`: 背景情報。

## 2. 思考プロセス (Chain-of-Thought) の標準化

重大な判断や複雑なコード実装の前に、`<thinking>` タグ内で以下の項目を検討することを義務付けます。

1.  **前提条件の確認:** 何が分かっていて、何が不明か。
2.  **リスク評価:** 既存機能への影響、セキュリティ、パフォーマンス。
3.  **代替案の比較:** 複数のアプローチを検討し、最善策を選択した理由。
4.  **検証計画:** どのようにテストし、成功を定義するか。

## 3. Few-shot & One-shot プロンプティング

-   **One-shot:** 複雑なアルゴリズムや特定のフォーマットが必要な場合、1つの完璧な例を提示するだけで精度が劇的に向上します。
-   **Few-shot:** 出力のトーンやスタイルを厳密に制御したい場合、複数の例を提示します。

## 4. 刺激プロンプト (Stimulus Prompting)

複雑な課題に対し、命令の最後に以下のような「刺激」を加えることで、モデルの注意力を高めます。
-   「このセキュリティチェックを通過しない限り、リリースは許可されません」
-   「効率性を極限まで追求し、計算量を最小限に抑えてください」

## 5. ロール・マスタリー (Role Mastery)

AIに与える役割（Architect, Developer, QA等）ごとに、その役割に特化した語彙と行動指針を定義したテンプレートを使用します。

## 6. プロンプト自己改善ループ

AIが生成した結果が期待に沿わない場合、単にやり直すのではなく、「プロンプトのどこに誤解を招く表現があったか」を自己分析し、プロンプト自体を修正してから再試行します。
