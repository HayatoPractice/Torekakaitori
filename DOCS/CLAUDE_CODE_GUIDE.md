# Claude Code 運用ガイド
# 読込タイミング：Claude Code / Gemini CLI 操作時・Git戦略確認時・自動化コマンド使用時

Claude Codeのツール特性を最大限に引き出し、自律的な開発サイクルを確立するためのガイドラインです。

## 1. コア・サイクル (Research-Strategy-Execution-Validation)

Claude Codeは以下の4ステップを基本単位として動作します。

1.  **Research (調査):** `grep_search`, `glob`, `read_file` を駆使して既存コードと構造を把握。
2.  **Strategy (戦略):** 調査結果に基づき、具体的な変更箇所と手順を決定。
3.  **Execution (実行):** `replace`, `write_file` によるコード修正。
4.  **Validation (検証):** `run_shell_command` によるビルド、テスト、リンター実行。

## 2. Model Context Protocol (MCP) の活用

外部データソースとの接続（Google Drive, Jira, Slack等）が必要な場合、MCPサーバーを介してコンテキストを拡張します。最新の外部ドキュメントが必要な場合は、`web_fetch` を利用して動的に情報を取得します。

## 3. Skills & Hooks による自動化

-   **Skills:** 頻繁に使用する一連の操作（例：PR作成、デプロイ準備）をスクリプト化し、再利用可能な「スキル」として定義します。
-   **Hooks:** 特定のアクション（コミット前、テスト後など）に連動して自動実行されるシェルコマンドを設定し、品質を担保します。

## 4. コンテキスト効率化プロトコル

-   **サージカル・エディット:** ファイル全体を書き換えるのではなく、`replace` ツールで必要な箇所のみを最小限に変更します。
-   **並列処理:** 複数の独立した `read_file` や `run_shell_command` は、`wait_for_previous: false` を活用して並列実行し、時間を短縮します。
-   **検索の最適化:** `grep_search` の `include_pattern` を絞り込み、不要なファイル読み込みを避けます。

## 5. 自律運用の限界と承認

-   **自走:** tech_stack内の実装、ドキュメント更新、テスト実行は自律的に行います。
-   **承認必須:** 外部APIキーの発行、課金、本番環境へのデプロイ、破壊的なディレクトリ変更は必ず人間の承認を得ます。

## 6. CLI コマンド完全リファレンス

### Gemini CLI スラッシュコマンド（`>>` プロンプトで使用）

| コマンド | 機能 | 活用シーン |
|---|---|---|
| `/chat list` | 保存済みチャットの一覧を表示 | 過去のセーブ名を確認したい時 |
| `/chat save <名前>` | 現在の会話を名前付きで保存 | 目的が変わる瞬間のセーブ点。`last` で統一すると楽 |
| `/chat resume <名前>` | 保存したチャットを読み込んで再開 | 前回の文脈を引き継いで続きから開始 |
| `/memory` | AIが覚えている前提知識を確認 | 保存を忘れても何を覚えているか確認 |
| `/quit` または `/exit` | Geminiを終了 | いつものターミナル（`$`）に戻る |

> **セーブ名を `last` に統一する運用が楽：** 終了時 `/chat save last` → 再開時 `/chat resume last`

### Claude Code コマンド

| コマンド | 機能 | 活用シーン |
|---|---|---|
| `claude --resume` | 直近の会話を引き継いで起動 | 昨日の最後の続きから即再開 |
| `claude-history` | 全自動録画された過去ログを検索・閲覧 | 3日前の神コードのカンニング・デバッグ記録参照 |
| `exit` または `quit` | Claudeを終了 | いつものターミナルに戻る |
| `Ctrl + C` | 実行中のツールを強制終了 | AIの長文回答を途中で止めたい時 |

### セキュリティ制限環境でのハイブリッド運用

社内ファイアウォールやSSO認証でClaudeの自動プッシュが拒否される場合：

```
1. Claudeに修正 + git commit まで行わせる
2. Claudeを終了（exit）
3. 人間がいつものターミナルから自分の手で git push を実行
```

## 7. Git 連携コマンドと「必勝黄金パターン」

### Gitコマンド一覧（Finder → GitHub の流れ）

| コマンド | 役割 | 活用シーン |
|---|---|---|
| `git checkout -b <ブランチ名>` | 新しい実験室（ブランチ）を作って切り替える | 本番コード（main）を汚さないための最初の一手 |
| `git checkout main` | 本番モードに切り替える | 実験がボツになった時・マージ後の同期 |
| `git add -A` | 全変更（追加・修正・**削除**）を記録対象にする | Finderでファイルを捨てた後、削除の事実もGitに伝える |
| `git commit -m "メッセージ"` | 手元にセーブポイントを作る | GitHubに送る前の手元での歴史の確定 |
| `git push origin <ブランチ名>` | ブランチをGitHubにアップロード | 完璧になったコードをGitHubに送る（まだ本番には反映されない） |
| `git pull` | GitHubの最新完成品をダウンロード | マージ後にFinderを最新状態に同期 |

### 必勝黄金パターン（5ステップ）

```
STEP 1  cd <フォルダ> && git checkout -b <実験室名>
        → 本番を汚さないパラレルワールドを作る

STEP 2  claude（またはgemini）を起動して実装・修正
        → 目的が変わるたびに /chat save でセーブ

STEP 3  Ctrl+C または exit でターミナルに戻る
        → テストが完璧になったタイミングで実行

STEP 4  git add -A → git commit -m "説明" → git push origin <ブランチ名>
        → GitHubに安全にアップロード

STEP 5  GitHubでマージ後 → git checkout main → git pull
        → Finderを綺麗に最新状態に保つ
```

### Git の魔法：知っておくべき仕組み

- **Finderには常に「1つのファイル」しか存在しない。** Gitが裏で「ファイルの歴史」を管理している。ブランチを切り替えると中身だけが自動で変身する。
- **マージは「足し算」だけでなく「削除・上書き」も含む。** 古いコードはマージの瞬間に自動で削除され、新しいコードに切り替わる。
- **本番を直接触るのは禁止。** すべての実験は実験室ブランチで行い、完成品だけを本番にマージする。

## 8. Antigravity 2.0 コマンドリファレンス

> Claude Codeと対応する概念として参照する。`/goal` や `@workspace` の思想は Claude Code 運用にも応用できる。

### 目的・自律実行・制御系コマンド

| コマンド | 機能 |
|---|---|
| `/goal [目標]` | 中間確認を挟まず、目標達成まで完全自律実行。テストが100%パスするまで継続 |
| `/grill-me [構想]` | AIから人間へ「逆質問」。仕様の考慮漏れを塞いでから安全に実装へ移る |
| `/schedule [指示]` | 1回限りまたは定期実行のスケジュールを登録してバックグラウンド自律駆動 |
| `/browser [指示・URL]` | ブラウザを起動してWebリサーチ・UIの視覚テストを実行 |
| `/tasks` | 実行中の全バックグラウンドタスクを監視・強制終了するコントロールパネル |
| `/fork` | 現在の開発スレッドから別ワークスペースを分岐。本番を汚さずに別パターンを試す |
| `/resume`（`/switch`） | 過去の会話セッション一覧から別スレッドに瞬時に切り替え |
| `/rewind`（`/undo`） | 以前の正常なチェックポイントまでコードと会話をロールバック |
| `/permissions` | 自律レベル（全自動・要確認・厳格）とブラウザ制限をコントロール |
| `/agents` | 並行稼働中のサブエージェントのCPU使用率・ステータスを監視 |

### 開発ワークフロー系コマンド（標準プラグイン）

| コマンド | 機能 |
|---|---|
| `/generate-unit-tests` | 現在開いているファイルのユニットテストを自動生成 |
| `/fix-errors` | 問題パネルの全エラー・警告を一括自動修正 |
| `/explain` | 選択したコードを人間がわかる言葉で詳細解説 |
| `/refactor` | 挙動を変えずに可読性・パフォーマンスを向上させるリファクタリング |
| `/document` | 選択した関数・クラスにJSDoc/docstringを自動付与 |
| `/deploy` | プロジェクト設定済みのデプロイワークフローを即時トリガー |

### エージェント用コンテキスト @メンションコマンド

| コマンド | 機能 |
|---|---|
| `@workspace` | プロジェクト全体のフォルダ・ファイル構造をコンテキストに含める |
| `@file` | 特定のファイルをピンポイントで参照させる |
| `@terminal` | 現在のターミナル出力（エラーログ・実行結果）をそのまま送信 |
| `@problems` | IDE内の全エラー・警告一覧をコンテキストに添付 |
| `@selection` | 現在マウス選択中のコードブロックのみを正確に渡す |
| `@codebase` | 全インデックス済みファイルを対象にセマンティック検索 |
| `@Supabase` | Supabase MCPに接続してDB構造・テーブル情報を参照 |
| `@Firebase` | Firebase MCPに接続してFirestore・Auth設定を参照 |
| `@Cloudflare` | Cloudflare MCPに接続してWorkersの環境・デプロイ状況を参照 |
| `@Linear` | Linear MCPでプロジェクト管理チケットの進捗を参照 |
| `@Vercel` | Vercel MCPでデプロイメントログ・ホスティングステータスを取得 |
