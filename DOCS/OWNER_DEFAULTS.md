▌SECTION 1：リソース制約（絶対に守る上限）

  週間開発時間：7〜10時間
    → 1プロジェクトに集中する場合：最大10時間
    → 3プロジェクト並行の場合：1つあたり平均2〜3時間/週

  同時進行プロジェクト上限：3つ
    → 4つ目を始める場合：既存の1つをkillまたは一時凍結してから開始
    → 凍結プロジェクトはFROZEN/フォルダに移動

  プロジェクトKill基準（いずれかに該当したら即判断）：
    □ 3ヶ月でユーザーからの反応（登録・問い合わせ・使用）がゼロ
    □ 6ヶ月でMRRが月間目標の30%未満
    □ Lv1仮説（「この市場にニーズがある」）が棄却された
    □ 自分が使わなくなった（自分用ツールの場合）

  Kill判断のフロー：
    → 即kill / ピボット（方向転換）/ 凍結（将来再開） の3択で判断
    → 凍結の場合：CONTEXT_BRIDGE.mdに再開条件を明記してFROZENへ

▌SECTION 2：技術スタック標準（迷ったらここを見る）

━━ 選定思想
  「多くの人に安く届ける・フリーミアムで運用する」という目標から逆算。
  → 無料枠が広い / 個人開発で実績豊富 / セキュリティが外部委託できる を優先。

━━ フロントエンド

  判断フロー（迷ったらこの順番で確認）：
    □ GAS WebApp → React + Vite（vite-plugin-singlefileで1ファイルHTML化必須）
    □ SEOが必要・外部公開・LP含む → Next.js + TailwindCSS
    □ 外部公開するSaaS・フリーミアム → Next.js + TailwindCSS
    □ 認証なし・自分専用・個人ツール → React + Vite + TailwindCSS
    □ 迷ったら → Next.js を選ぶ（後からSEO・API追加が楽）

  【Aコース】React + Vite + TailwindCSS
    理由：現在の主力スタック・学習コスト不要・エコシステムが成熟
    用途：シングルページアプリ・GAS WebApp組み込み・認証なし個人ツール

  【Bコース】Next.js + TailwindCSS
    理由：SEO対応・SSR・API Routes内蔵・Vercelと相性抜群
    用途：外部公開Webサービス・LPが必要なもの・SEOが重要なもの・フリーミアムSaaS
    習得難易度：React習得後なら低（同じReact構文）

  【注意】GAS WebAppの場合：vite-plugin-singlefileで1ファイルHTML化が必須

━━ バックエンド / DB

  【第1選択】Supabase
    無料枠：500MB DB・50MB ストレージ・50,000 月間アクティブユーザー
    強み：PostgreSQL + Auth + Storage + リアルタイム + RLS（行レベルセキュリティ）が全部入り
    用途：ユーザー管理が必要なアプリ全般
    コスト：個人開発レベルなら無料枠で十分・スケール時は$25/月〜

  【第2選択】Firebase（Firestore）
    無料枠：1GB DB・Spark（無料）プランで十分スタートできる
    強み：リアルタイムDB・Google認証との相性・Googleエコシステム
    用途：リアルタイム更新が必要なアプリ・既にGCP使用中の場合

  【第3選択】Google スプレッドシート（GAS経由）
    用途：個人ツール・データ量が少ない・管理画面が不要な場合のみ
    注意：外部ユーザーが増えたら必ずSupabase/Firebaseに移行する

  【第2選択】Firebase Auth（DBにFirebase使用時）
  ※ 独自実装禁止（セキュリティ最優先方針に準拠）

  採用する条件（ユーザーが明示的に指定した場合のみ）：
    □ スプレッドシートとの密な連携が必要
    □ 自分だけが使う簡単な自動化ツール
    □ Google Workspace（Gmail・Drive・Calendar）との統合が中心
  それ以外は基本的にWebアプリ（React/Next.js）を採用する。
  詳細：DOCS/GAS_DEVELOPMENT_GUIDE.md を参照

━━ モバイルアプリ（暫定方針）

  【推奨：Expo（React Native ベース）】
    理由：JS/TSで書けるためWeb開発の知識が流用できる・最も学習コストが低い・OTAアップデート可
    習得難易度：低（React知識があればすぐ始められる）
    用途：プッシュ通知・カメラ・GPS等ネイティブ機能が必要な場合
    ※ 作成時に「Expo / React Native / Flutter のどれか」を社長に確認する

  【参考：Flutter（必要に応じて）】
    理由：高パフォーマンス・UIの一貫性・Google製
    習得難易度：中（Dart言語の学習が必要）
    用途：パフォーマンスが最優先・Expoでカバーできない機能が必要な時

  ⚠️ 「完全無料のみ」採用判断基準：
    一部でも有料課金が存在するライブラリ・サービスは採用しない。
    判断例：MUIのDataGrid Pro（有料）→ MUI自体も採用禁止。
            HeroUI（完全無料）→ 参照専用として可。

▌SECTION 3：収益化・価格設定スタンダード

━━ 基本モデル：フリーミアム（Free + 有料プラン）

  無料プランの設計思想：
    → 「価値を感じてもらえる最小限の機能」を無料で提供する
    → 無料で使い続けても怒られない・でも有料の魅力が伝わる設計
    → 無料プランのコスト（サーバー・API等）が収益を圧迫しないか確認する

  有料プランのトリガー（ユーザーが課金したくなる条件）：
    → 制限解除（件数・頻度・履歴保存期間）
    → 高度な機能（AI分析・エクスポート・複数デバイス同期）
    → サポート優先・広告非表示

━━ 価格設定ルール

  基本方針：「競合の平均より安く・少しでも利益が出る価格」
  設定手順：
    STEP 1｜競合3〜5サービスの価格を調査する
    STEP 2｜その平均価格の70〜80%を基準にする
    STEP 3｜月10人有料転換でコスト回収できるか計算する
    STEP 4｜価格は小さく始めて、価値が証明されたら上げる

  価格帯の目安（変更可）：
    月額：¥300〜¥980（競合が¥1,000前後のもの）
    買い切り：¥1,980〜¥4,980
    ※ この数値はサービスにより毎回調整する。価格設定の根拠は REQUIREMENTS_LOG.mdの「技術選定記録」、またはプロジェクトルート直下の GTM_PLAN.md（任意・社長が作成）に記録する。

━━ 公開サービス向け市場選定基準

  基本方針：「多くの人に安く役に立つ」
    → ニッチすぎる市場（1,000人未満の潜在ユーザー）は避ける
    → 自分が実際に感じた問題を解決するものを優先する
    → 競合が強すぎる市場（Google・Notion等が完全に支配）は避ける

  市場選定チェック（公開サービスのみ・プロジェクト開始前に確認）：
    □ 潜在ユーザーは1万人以上いるか
    □ 自分がそのユーザーに近いか（共感できるか）
    □ 競合がいるか（いなければ市場がない可能性）
    □ 競合より何かひとつで勝てるか（価格・速度・UX・特定機能）

▌SECTION 7：型安全スタック標準（仕組み #TS）

【基本方針】
  全てのプロジェクトで「型安全な言語/ツール」を使って開発し、デプロイ時に最終変換する。
  これにより、型エラーをコーディング中に発見でき、デバッグのトークン消費を60〜80%削減できる。

【言語別ルール】
  ✅ JavaScript  → TypeScript (.ts / .tsx) で作成。デプロイ時のみ .js にコンパイル。
  ✅ CSS         → Tailwind CSS を使用。素の CSS / SCSS は最小限。
  ✅ Python      → mypy を使った型アノテーション必須。
  ✅ HTML        → JSX / TSX 形式を優先（React プロジェクト）。

【tsc watchモード自動起動】
  VSCode起動時  : .vscode/tasks.json の "runOn": "folderOpen" により自動起動する。
  Antigravity  : CLAUDE.md の指示により、セッション開始時に確認・起動する。
  起動コマンド : npx tsc --noEmit --watch（型チェックのみ、出力ファイルなし）

【型エラー発覚時の強制ルール（AIへの指示）】
  ✅ 型エラーが発覚した時点で即座に作業を止め、根本原因を特定してから修正する。
  ✅ エラーを無視して先に進むことは禁止。修正完了後に作業を再開する。
  ✅ 同一エラーで3回失敗した場合は即座に中断し、別のアプローチを社長に提案する。

【コース別の適用方針】
  Aコース（Vanilla JS）:
    - TypeScript + esbuild または tsc でコンパイルして .js を出力
    - tsconfig.json: "target": "ES2017", "module": "ESNext"
  Bコース（Next.js）:
    - 標準で TypeScript 対応（create-next-app --ts で初期化）
    - tsconfig.json は Next.js のデフォルトを使用

【基本方針】
プロジェクト開始時に採用した全ライブラリのバージョンを固定し、
意図しないAPI変更によるバグを防ぐ。

【手順】
  STEP 1｜npm install 後、package.json の dependencies/devDependencies を
           REQUIREMENTS_LOG.mdの「外部ライブラリ管理」セクションにコピーする
  STEP 2｜コード実装時は、記録されたバージョンのAPIと記法のみ使用する
  STEP 3｜バージョンアップは社長の明示的な承認なしに行わない
  STEP 4｜アップグレード後は必ず `npx tsc --noEmit` で全型エラーを確認してから進める

  □ @ai-sdk/google v3：googleSearch({}) の引数は必須（ML-003）
