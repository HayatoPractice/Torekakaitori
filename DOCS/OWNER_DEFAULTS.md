▌SECTION 1：リソース制約（絶対に守る上限）

  週間開発時間：7〜10時間
    → 1プロジェクトに集中する場合：最大10時間
    → 3プロジェクト並行の場合：1つあたり平均2〜3時間/週

  同時進行プロジェクト上限：3つ
    → 4つ目を始める場合：既存の1つをkillまたは一時凍結してから開始
    → 凍結プロジェクトはFROZEN/フォルダに移動

  プロジェクトKill基準（いずれかに該当したら即判断）：
    □ 3ヶ月でユーザーからの反応（登録・問い合わせ・使用）がゼロ
    □ 6ヶ月でMRRが月間目標の30%未満
    □ Lv1仮説（「この市場にニーズがある」）が棄却された
    □ 自分が使わなくなった（自分用ツールの場合）

  Kill判断のフロー：
    → 即kill / ピボット（方向転換）/ 凍結（将来再開） の3択で判断
    → 凍結の場合：CONTEXT_BRIDGE.mdに再開条件を明記してFROZENへ

▌SECTION 2：技術スタック標準（迷ったらここを見る）

━━ 選定思想
  「多くの人に安く届ける・フリーミアムで運用する」という目標から逆算。
  → 無料枠が広い / 個人開発で実績豊富 / セキュリティが外部委託できる を優先。

━━ フロントエンド

  【第1選択】React + Vite + TailwindCSS
    理由：現在の主力スタック・学習コスト不要・エコシステムが成熟
    用途：シングルページアプリ・GAS WebApp組み込み

  【第2選択】Next.js + TailwindCSS
    理由：SEO対応・SSR・API Routes内蔵・Vercelと相性抜群
    用途：外部公開Webサービス・LPが必要なもの・SEOが重要なもの
    習得難易度：React習得後なら低（同じReact構文）

  【注意】GAS WebAppの場合：vite-plugin-singlefileで1ファイルHTML化が必須

━━ バックエンド / DB

  【第1選択】Supabase
    無料枠：500MB DB・50MB ストレージ・50,000 月間アクティブユーザー
    強み：PostgreSQL + Auth + Storage + リアルタイム + RLS（行レベルセキュリティ）が全部入り
    用途：ユーザー管理が必要なアプリ全般
    コスト：個人開発レベルなら無料枠で十分・スケール時は$25/月〜

  【第2選択】Firebase（Firestore）
    無料枠：1GB DB・Spark（無料）プランで十分スタートできる
    強み：リアルタイムDB・Google認証との相性・Googleエコシステム
    用途：リアルタイム更新が必要なアプリ・既にGCP使用中の場合

  【第3選択】Google スプレッドシート（GAS経由）
    用途：個人ツール・データ量が少ない・管理画面が不要な場合のみ
    注意：外部ユーザーが増えたら必ずSupabase/Firebaseに移行する

━━ 認証

  【第1選択】Supabase Auth（DBにSupabase使用時）
  【第2選択】Firebase Auth（DBにFirebase使用時）
  ※ 独自実装禁止（セキュリティ最優先方針に準拠）

━━ 決済

  【唯一の選択】Stripe
  ※ 他の決済サービスへの変更は社長承認必須

▌SECTION 3：収益化・価格設定スタンダード

━━ 基本モデル：フリーミアム（Free + 有料プラン）

  無料プランの設計思想：
    → 「価値を感じてもらえる最小限の機能」を無料で提供する
    → 無料で使い続けても怒られない・でも有料の魅力が伝わる設計
    → 無料プランのコスト（サーバー・API等）が収益を圧迫しないか確認する

  有料プランのトリガー（ユーザーが課金したくなる条件）：
    → 制限解除（件数・頻度・履歴保存期間）
    → 高度な機能（AI分析・エクスポート・複数デバイス同期）
    → サポート優先・広告非表示

━━ 価格設定ルール

  基本方針：「競合の平均より安く・少しでも利益が出る価格」
  設定手順：
    STEP 1｜競合3〜5サービスの価格を調査する
    STEP 2｜その平均価格の70〜80%を基準にする
    STEP 3｜月10人有料転換でコスト回収できるか計算する
    STEP 4｜価格は小さく始めて、価値が証明されたら上げる

  価格帯の目安（変更可）：
    月額：¥300〜¥980（競合が¥1,000前後のもの）
    買い切り：¥1,980〜¥4,980
    ※ この数値はサービスにより毎回調整する。GTM_PLAN.mdに記録する。

▌SECTION 4：ターゲット市場の基準

  基本方針：「多くの人に安く役に立つ」
    → ニッチすぎる市場（1,000人未満の潜在ユーザー）は避ける
    → 自分が実際に感じた問題を解決するものを優先する
    → 競合が強すぎる市場（Google・Notion等が完全に支配）は避ける

  市場選定チェック（プロジェクト開始前に必ず確認）：
    □ 潜在ユーザーは1万人以上いるか
    □ 自分がそのユーザーに近いか（共感できるか）
    □ 競合がいるか（いなければ市場がない可能性）
    □ 競合より何かひとつで勝てるか（価格・速度・UX・特定機能）

▌SECTION 5：法務・利用規約（外部ユーザーへのサービス提供時）

  プライバシーポリシーが必要な条件（いずれかに該当したら必須）：
    □ ユーザー登録・ログイン機能がある
    □ Google Analytics・Firebase Analytics等の解析ツールを使う
    □ メールアドレスを収集する
    □ Cookieを使う

  利用規約が必要な条件：
    □ 不特定多数のユーザーに使わせる（無料でも）
    □ 有料サービスを提供する

  対応方法（現時点）：
    → Phase 1（最初の100人）まで：簡易テンプレートをベースに作成
    → Phase 2（スケール）以降：弁護士監修を検討
    → テンプレート参考：「みんなの利用規約」「プライバシーポリシー生成ツール」
