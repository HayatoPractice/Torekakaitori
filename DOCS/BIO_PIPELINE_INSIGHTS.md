# プロンプトベース・パイプライン構築の知見

複雑な多段階プロセス（バイオインフォマティクス・パイプライン等）をLLMで構築する際の研究に基づいた知見です。

## 1. 離散的ステップへの分解

タスクを単一の大きな命令として与えるのではなく、各ステップを「入力・処理・出力」が明確な独立したパーツとして定義します。これにより、エラーの特定と修正が容易になります。

## 2. 外部知識の動的注入 (External Knowledge Ingestion)

モデルの学習データに含まれていない最新のツールやAPIを使用する場合、以下の情報をプロンプトに動的に注入します。
-   最新のREADME、公式ドキュメント。
-   動作確認済みの最小構成のコード断片。
-   よくあるエラーメッセージとその解決策。

## 3. パイプラインの進化 (Pipeline Evolution)

既存のコードやツールが時代遅れになった場合、以下のプロセスで進化させます。
1.  現在のツールの制約を特定。
2.  代替となる最新ツールの調査（web検索・MCP活用）。
3.  旧ツールと新ツールのインターフェース（入出力形式）の差異を吸収するブリッジコードの実装。

## 4. 実証的バグ再現 (Empirical Reproduction)

「おそらくこうだろう」という推測での修正を禁じ、以下の手順を徹底します。
1.  バグを確実に再現する最小のテストスクリプトを作成。
2.  テストが失敗することを確認（Red）。
3.  修正を行い、テストが通過することを確認（Green）。

## 5. 構造化出力の厳格化

パイプライン間のデータ受け渡しは、型定義されたJSONや構造化されたXMLを使用し、パースエラーによるパイプラインの停止を防ぎます。
