| サービス | 用途・特徴 | 個人開発での優先度 |

| **Cloud Run** | コンテナ化アプリの自動スケーリング。リクエストに応じた実行・管理不要 | ★★★ 第1候補 |
| **Cloud Functions** | イベント駆動型（ファイルアップロード・DB変更等に反応）のサーバーレス関数 | ★★★ 第1候補 |
| App Engine | 言語・フレームワークを問わないPaaSアプリ実行。バージョン管理・トラフィック分割 | ★★ 中規模向け |

| Cloud Batch | 大規模な計算ジョブのスケジューリング・並列処理 | ★ AI/ML用途 |

## §O バックグラウンド自動化 — 設計パターン6選

> 「/schedule」コマンドや GitHub Actions・Cloud Schedulerで実装できる夜間・定期自動実行のパターン集。

### パターン1：深夜の依存ライブラリ自動アップデート＋回帰テスト

```
トリガー：毎週金曜 深夜 AM 2:00
処理内容：
  1. 全外部ライブラリのセキュリティ修正・アップデートを自動スキャン
  2. 更新がある場合、コードを自動更新
  3. システム全体の回帰テスト（単体・結合）を全自動実行
  4. テストをクリアした差分（Diff）を翌朝提示
朝の状態：承認ボタンを押すだけで本番に統合完了
```

### パターン2：朝イチのコード品質監査

```
トリガー：毎朝 AM 6:00
処理内容：
  1. 前日に書き換えたコードを全巡回スキャン
  2. バグの引き金・パフォーマンス低下・セキュリティ脆弱性を自律検出
  3. 問題箇所の修正コードを組み立てる
  4. 修正リストと修正パッチコードをAM 9:00に提示
朝の状態：人間のレビュー時間を大幅削減
```

### パターン3：仕様書の定時自動更新

```
トリガー：毎週定期（または数日おき）
処理内容：
  1. 全ソースコードを自動解析
  2. 新機能・変更されたAPIの構造を読み取る
  3. README.md・API仕様書をプログラムの実態に合わせて自動更新
効果：コードと仕様書の「修正漏れによる食い違い」を永久にゼロにする
```

### パターン4：デッドコード定期クリーンアップ

```
トリガー：毎週水曜 AM 3:00
処理内容：
  1. リポジトリ全体に静的解析（AST解析）を実行
  2. どこからも呼ばれていない関数・重複ロジック・不要インポートを検出
  3. 自動で削除・リファクタリング
  4. テストをパスした結果を翌朝提示
朝の状態：「32箇所クリーンアップしました。テスト全通過」という結果が届く
```

### パターン5：エラーログの夜間自動解析＋修正パッチ生成

```
トリガー：毎晩 24:00
処理内容：
  1. その日のサーバーエラーログ（スタックトレース）を収集・巡回
  2. ソースコードの行レベルでバグ原因を特定
  3. 修正コードと再発防止テストコードを自動生成
朝の状態：「昨日の不具合の修正案を用意しました。マージすれば解決します」
```

### パターン6：最新脆弱性（CVE）自動検知＋ホットフィックス

```
トリガー：毎日 AM 4:00
処理内容：
  1. バックグラウンドブラウザで最新CVEデータベースを自動リサーチ
  2. 自プロジェクトのOSSに危険な脆弱性が報告されたか検知
  3. 安全なパッチバージョンへのアップデートをコードに適用
  4. セキュリティテストを実行してPRを自動作成
朝の状態：「危険度高の脆弱性を検知。安全なバージョンへ移行するPRを作成しました」
```
