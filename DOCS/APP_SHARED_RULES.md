# APP_SHARED_RULES.md — AI共通行動指針

このファイルは全プロジェクト共通のAI行動指針をまとめたものです。
**原本で管理し、各プロジェクトに配布する。変更は必ず原本側で行うこと。**

---

## 1. プロアクティブ提案

→ 詳細ルールは `DOCS/SERVICE_ORG_CORE.md`「積極的提案ルール」を参照すること。
要約：同じ問題の繰り返し・エラーが解消されない・迷いが見える場合に、押しつけにならないトーンで解決策を提案する。

---

## 2. 実装前の影響範囲チェック

コードや設定を変更する前に、影響を受ける可能性のある他のファイル・コンポーネント・APIを自分から確認する。
変更点が広範囲に及ぶ場合は、実装前にユーザーに一言伝える。

---

## 3. 仮説ベースのデバッグ

→ 詳細手順は `DOCS/SERVICE_ORG_CORE.md`「バグ修正時の仮説デバッグ手順（STEP 1〜5）」を参照すること。
要約：症状記述 → 原因候補3つ列挙 → 最有力から検証 → 同一エラー3回失敗で社長に報告。

---

## 4. コンテキスト消費量の自動警告

会話のやり取りが長くなってきたと感じたら、自分から提案する：
「そろそろ CONTEXT_BRIDGE.md を更新して次のセッションに備えますか？」
情報が消えるリスクを防ぐために、引き継ぎ準備を積極的に促す。

---

## 5. 決定理由の自動メモ

ライブラリ・設計・実装方針を選択したとき、「なぜそれを選んだか」を関連する DOCS ファイルに簡潔に残す。
次のセッションで「なぜこの実装にしたのか」が分かるようにする。

---

## 6. 目標逆算チェック

個別の依頼（例：「このボタンを直して」）を受けたとき、プロジェクトの本来の目標に照らして
「それだけでは不十分」な場合や「別の問題が根本にある」場合は、一言指摘する。
ただし、指摘は簡潔に。ユーザーが判断できるよう情報を提供する程度にとどめる。

---

## 7. インシデント管理（必須）

→ **詳細手順は `CLAUDE.md` 起動シーケンス STEP 3 を正本として参照すること。**

各プロジェクトの CLAUDE.md が一元管理している。本ファイルはその存在を周知するためのポインタ。

要約：
- **起動時**：インシデント管理フォルダの `_PRE_CHECKLIST.md` と `INCIDENT_INDEX.md` を確認
- **機能追加・編集・削除のたびに**：INCIDENT_INDEX.md で関連タグを照合（1回だけでなく都度）
- **不具合解決後**：即時記録（セッション終了まで持ち越さない）
- **目的**：同じミスをゼロにする。全アプリの失敗を資産に変える

---

## 8. コード修正・ファイル編集時の必須注意事項（修正を行う全タイミングで適用）

**このルールはバグ修正・機能追加・ドキュメント更新のいずれにも適用する。**

### 8-1. 修正前チェック（着手前に必ず実施）

1. **影響範囲の特定**：修正対象ファイルを `grep` で逆引きし、他ファイルから参照されているか確認する
   ```bash
   grep -r "対象ファイル名\|対象関数名" . --include="*.md" --include="*.py" --include="*.sh"
   ```
2. **クロスファイル副作用チェック（6視点）**：
   - 視点①：同じ変数名・関数名・セクション名を他のファイルが参照していないか
   - 視点②：修正によってドキュメント間の「参照先」が存在しなくなっていないか
   - 視点③：スクリプトファイルを修正する場合、呼び出し元スクリプトへの影響がないか
   - 視点④：DOCS_INDEX.md のタスク別早見表からのリンクが壊れないか
   - 視点⑤：sync_to_apps.py の同期対象リストに影響がないか（新規ファイル追加時）
   - 視点⑥：CLAUDE.md や AGENTS.md から参照されているセクション名を変えていないか

### 8-2. スクリプト修正時の追加ルール

- `sync_to_apps.py`：修正後は必ず `--dry-run` モードで動作確認する
  ```bash
  python3 scripts/sync_to_apps.py --dry-run
  ```
- `post-merge` / `install_hooks.sh`：修正後は `bash -n スクリプト名` で構文チェックする
  ```bash
  bash -n scripts/post-merge
  bash -n scripts/install_hooks.sh
  ```
- `setup_auto_sync.sh`：このファイルは **廃止済み（launchd方式）** のため、原則として修正・実行しない

### 8-3. ドキュメント修正時の追加ルール

- **セクション名の変更は連鎖修正が必要**：`## セクション名` を変更すると、他のMDファイルが参照している可能性がある
  - 変更前に `grep -r "旧セクション名" DOCS/` で全参照を確認してから変更する
- **CLAUDE.md の `## セクション名` 変更は `sync_to_apps.py` の `STANDARD_CLAUDE_SECTIONS` 変更も必要**
  - 変更後は `sync_to_apps.py` の L48-55 も合わせて更新すること

### 8-4. セッション終了時チェックリスト（毎回確認）

セッション終了前に以下を確認する：
- [ ] 新しいアプリ種別・ライブラリ・ツールを採用した場合 → `CROSS_REFERENCE.md` §1 に追記する
- [ ] 新しいパターンを発見した場合 → `CROSS_REFERENCE.md` §5 と `MASTER_LESSONS.md` に追記する
- [ ] `LEARNING_LOG.md` に今日の記録を追記する（500行を超えたら `LEARNING_LOG_ARCHIVE.md` に古い記録を移す）
- [ ] `CONTEXT_BRIDGE.md` を最新の状態に更新する

---

## 9. LEARNING_LOG.md ローテーションルール

LEARNING_LOG.md が **500行を超えた場合**、以下の手順でローテーションする：

1. `DOCS/LEARNING_LOG_ARCHIVE.md` を作成（なければ新規）
2. 最も古い記録（LL-001から順番に）を `LEARNING_LOG_ARCHIVE.md` の末尾に移動する
3. `LEARNING_LOG.md` の「学習ログ一覧（インデックス）」テーブルから移動分を削除する
4. アーカイブ済みの記録は `MASTER_LESSONS.md` への昇格が済んでいるか確認する

> ローテーション基準：500行 / 理由：AIのコンテキスト読込コスト最小化
