# SHARED_RULES.md — AI共通行動指針

このファイルは全プロジェクト共通のAI行動指針をまとめたものです。
**原本で管理し、各プロジェクトに配布する。変更は必ず原本側で行うこと。**

---

## 1. プロアクティブ提案

→ 詳細ルールは `DOCS/SERVICE_ORG_CORE.md`「積極的提案ルール」を参照すること。
要約：同じ問題の繰り返し・エラーが解消されない・迷いが見える場合に、押しつけにならないトーンで解決策を提案する。

---

## 2. 実装前の影響範囲チェック

コードや設定を変更する前に、影響を受ける可能性のある他のファイル・コンポーネント・APIを自分から確認する。
変更点が広範囲に及ぶ場合は、実装前にユーザーに一言伝える。

---

## 3. 仮説ベースのデバッグ

→ 詳細手順は `DOCS/SERVICE_ORG_CORE.md`「バグ修正時の仮説デバッグ手順（STEP 1〜5）」を参照すること。
要約：症状記述 → 原因候補3つ列挙 → 最有力から検証 → 同一エラー3回失敗で社長に報告。

---

## 4. コンテキスト消費量の自動警告

会話のやり取りが長くなってきたと感じたら、自分から提案する：
「そろそろ CONTEXT_BRIDGE.md を更新して次のセッションに備えますか？」
情報が消えるリスクを防ぐために、引き継ぎ準備を積極的に促す。

---

## 5. 決定理由の自動メモ

ライブラリ・設計・実装方針を選択したとき、「なぜそれを選んだか」を関連する DOCS ファイルに簡潔に残す。
次のセッションで「なぜこの実装にしたのか」が分かるようにする。

---

## 6. 目標逆算チェック

個別の依頼（例：「このボタンを直して」）を受けたとき、プロジェクトの本来の目標に照らして
「それだけでは不十分」な場合や「別の問題が根本にある」場合は、一言指摘する。
ただし、指摘は簡潔に。ユーザーが判断できるよう情報を提供する程度にとどめる。

---

## 7. インシデント管理（必須）

### 起動時の確認（スキップ禁止）

セッション開始時、必ず以下のパスを確認する：
```
/Users/sasakihayato/アプリ作成関連/アプリ作成/インシデント管理/
```
1. `_PRE_CHECKLIST.md` を読み、全チェック項目を確認する
2. `INCIDENT_INDEX.md` の「技術スタック別クイック検索」でこのプロジェクトの技術と照合する
3. 関連ファイルだけを読む（全ファイルを読む必要はない）
4. 類似事例があれば起動報告に「⚠️ 類似インシデント検出：[ファイル名]」を含める

### 機能追加・編集・削除のたびの確認（スキップ禁止）

新機能を追加・既存機能を編集・機能を削除するたびに、作業開始前に必ず以下を確認する：
（起動時の1回だけでなく、作業の単位ごとに都度実施すること）
1. `INCIDENT_INDEX.md` の「技術スタック別クイック検索」で作業に関係するタグを照合する
2. 関連インシデントがあれば「⚠️ 関連インシデントあり：[INC-XXX]」と社長に一言伝えてから作業を開始する
3. `_PRE_CHECKLIST.md` の該当チェック項目を確認し、チェック済みであることを確認する

### 不具合解決後の記録（スキップ禁止）

不具合・ミス・予期しない問題を解決したら、**その場で即時**以下の手順で記録する。
セッション終了まで持ち越さない。解決した直後に記録すること。
1. `_TEMPLATE.md` をコピーしてインシデントファイルを作成（ファイル名：`YYYY-MM-DD_[アプリ名]_[概要].md`）
2. frontmatter の `tags:` に関連技術タグを正確に記入する
3. `INCIDENT_INDEX.md` の全インシデント一覧・技術スタック別クイック検索・カテゴリ別統計を更新する（INC番号を採番）
4. `_PRE_CHECKLIST.md` にそのインシデントの「今後の予防策」を追記する
5. 汎用パターンが見つかったら `アプリ作成原本/DOCS/MASTER_LESSONS.md` にも昇格させる

### セッション終了前の確認（スキップ禁止）

`CONTEXT_BRIDGE.md` を更新する前に、必ず以下を確認する：
- 今セッションで解決した不具合・ミスは全てインシデント管理フォルダに記録済みか？
- 未記録のものがあれば、CONTEXT_BRIDGE更新より先にインシデント記録を完了させる

### 目的

同じミスをゼロにする。全アプリの失敗を資産に変え、新規開発時に必ず活用する。
