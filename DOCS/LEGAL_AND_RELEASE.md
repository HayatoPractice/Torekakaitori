> **読み込みタイミング：** 本番デプロイ・アプリリリース前の最終確認時、および法的コンプライアンスが関係するコード実装時
> このファイルは分散していたリリース・法務ルールの **ナビゲーターファイル** です。

> 📌 **汎用エッセンス（全プロジェクト共通の価値ある知見）**
> - 本番デプロイ前は必ず5ステップの確認フロー（品質→セキュリティ→法務→承認→デプロイ）を踏む

> - プライバシーポリシー・利用規約は公開前に必ず法務確認する
> （全体の汎用知見は DOCS/ESSENCE_INDEX.md に集約）

## 1. リリース前の必須確認フロー（このフローを全て完了してから社長に承認を求める）

```
Step 1: 品質・パフォーマンス確認  → APP_DESIGN_STANDARDS.md §2 を読み込んでチェック
Step 2: セキュリティ確認         → SERVICE_ORG_CORE.md「③ OWASP Top 10 チェックリスト」を読み込んでチェック
Step 3: 法的コンプライアンス確認  → LEGAL_COMPLIANCE.md を読み込んでチェック（業種別要件を含む）
Step 4: デプロイ承認             → 以下 §2 の確認チェックリストを全てクリアしてから社長へ承認依頼
Step 5: 本番デプロイ             → 社長承認後、社長が実際のデプロイ操作を行う
```

> **デプロイ操作は社長（人間）のみが実施。AI は実行コマンドを提案・確認はするが、本番環境へのデプロイ操作は絶対に行わない。**

## 2. デプロイ承認前チェックリスト（全て ✅ になったら承認依頼）

### 2-1. 機能・品質

- [ ] dev 環境での実装・verify・デモが全て完了している
- [ ] Lighthouse スコア 70 以上（リリース不可ラインをクリア）
- [ ] Core Web Vitals 全指標がリリース不可ラインをクリア（APP_DESIGN_STANDARDS.md §2-1 参照）
- [ ] モバイル（375px）・タブレット（768px）・デスクトップ（1024px）全幅で正常動作する
- [ ] TypeScript 型チェック（`npx tsc --noEmit`）にエラーがない
- [ ] npm audit / Snyk で High 以上の脆弱性がゼロである

### 2-2. セキュリティ

- [ ] OWASP A01〜A10 の全項目を確認した（`SERVICE_ORG_CORE.md` §OWASP 参照）
- [ ] Severity「High」以上の脆弱性が残っていない
- [ ] 無料プランのユーザーが有料機能 API を直接叩けないことを確認した
- [ ] ハードコーディングされたシークレット・APIキーがコードに含まれていない

### 2-3. 法的コンプライアンス

- [ ] `LEGAL_COMPLIANCE.md` の「個人情報保護法・特商法」の必須対応を確認した
- [ ] 対象業種（医療・金融・不動産等）がある場合、業種別要件を確認した
- [ ] 禁止表現（誇大広告・効果の断言）が含まれていない

### 2-4. バージョン管理

- [ ] git タグを付けた（例：`git tag v1.0.0`）
- [ ] プレリリースの場合は `v1.0.0-beta.1` 形式のタグを使用している
- [ ] `main` ブランチに直接コミットせず、`develop` からマージしている

## 3. デプロイルール（環境定義）

| 環境 | 説明 | 変更権限 |
|:---|:---|:---|
| `dev`（開発） | ローカル環境・AI が自由に変更可能 | AI・開発者 |
| `prod`（本番） | 実際のユーザーが使う環境 | 社長（承認後のみ） |

**本番デプロイ後に問題が発生した場合：即座に社長に報告して指示を仰ぐ。AIがロールバックを提案する場合も、実行は社長が行う。**

---

## 4. 法的コンプライアンスの詳細

→ 詳細は `DOCS/LEGAL_COMPLIANCE.md` を読み込むこと（本ファイルはナビゲーターのみ）。

主要な確認項目（概要）：
- **個人情報保護法**：メールアドレス・氏名・決済情報の取り扱い、プライバシーポリシー設置
- **特定商取引法**：有料サービスの場合は特商法表記が必要
- **業種別禁止表現**：医療（効果の断言禁止）・金融（利回り確約禁止）・不動産（内容虚偽禁止）
- **知的財産**：外部ライブラリのライセンス確認、コンテンツ著作権の確認
